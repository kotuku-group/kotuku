[[sec-migration-equality]]
=== Equality and Inequality Operators
Lua's `==` operator is replaced by the `is` keyword.  The `~=` inequality operator is replaced by `!=`.

[source,tiri]
----
-- Lua
if x == nil then ... end
if y ~= 0 then ... end

-- Tiri
if x is nil then ... end
if y != 0 then ... end
----

The semantics are identical to Lua's equality: two values are equal if they have the same type and the same value, or if a `__eq` metamethod returns true.  See <<ch-operators>> for the complete operator reference.

[[sec-migration-operators]]
=== Changed Operators

[discrete]
==== Exponentiation

In standard Lua, `^` is the exponentiation operator.  In Tiri, `^` is bitwise XOR and `**` is exponentiation.

[source,tiri]
----
-- Lua
result = 2 ^ 10       -- 1024

-- Tiri
result = 2 ** 10      -- 1024
result = 0xFF ^ 0x0F  -- bitwise XOR: 240
----

[discrete]
==== Bitwise Operators

The `bit.*` library is removed.  Tiri provides native C-style bitwise operators on 32-bit integers:

[cols="2,3"]
|===
|Operator |Description

|`~x`     |Bitwise NOT
|`a & b`  |Bitwise AND
|`a \| b` |Bitwise OR
|`a ^ b`  |Bitwise XOR
|`a << b` |Left shift
|`a >> b` |Right shift
|===

[source,tiri]
----
-- Lua (with bit library)
local masked = bit.band(flags, 0xFF)
local shifted = bit.lshift(1, 4)

-- Tiri
masked = flags & 0xFF
shifted = 1 << 4
----

Compound bitwise assignment operators (`&=`, `|=`, `^=`) do not exist.  Use `x = x & y` instead.

[[sec-migration-arithmetic-coercion]]
=== String-to-Number Coercion

indexterm:[Lua, coercion] indexterm:[coercion, arithmetic] Standard Lua coerces a string that represents a valid number into a number for arithmetic and for the `bit.*` library, so `'10' + 5` yields `15` and `bit.band('12', 5)` yields `4`.  Tiri performs no such coercion: a string operand raises an error in every arithmetic and bitwise operator.  Convert the operand with `tonumber()`.

[source,tiri]
----
-- Lua
total = '10' + 5             -- 15
masked = bit.band('12', 5)   -- 4

-- Tiri
total = '10' + 5             -- error: attempt to perform arithmetic on a string value
masked = '12' & 5            -- error: number expected, got string

total = tonumber('10') + 5   -- 15
masked = tonumber('12') & 5  -- 4
----

The rule covers both operands of a binary operator, the shift count of `<<` and `>>`, and the operand of the `has` operator (<<sec-flag-testing-operator>>).  The ordering operators reject a string operand on the same terms, so no operator in Tiri coerces one; see <<sec-bitwise-operators>> and <<sec-comparison-operators>>.

This affects the values that arrive from string sources, including command-line arguments (<<sec-script-arguments>>), parsed configuration and text fields.  Apply `tonumber()` at the point the value is read, rather than at each operator that consumes it.

[[sec-migration-indexing]]
=== Zero-Based Indexing
indexterm:[Lua, indexing] Tiri uses zero-based indexing for tables, strings and arrays.  In standard Lua, the first element of a table is at index 1 and `string.sub()` starts at position 1.  In Tiri, the first element is at index 0.

[source,tiri]
----
-- Lua: first element is t[1]
-- Tiri: first element is t[0]
t = { 'a', 'b', 'c' }
print(t[0])   -- 'a'
print(t[1])   -- 'b'

-- Lua: string.sub(s, 1, 3)
-- Tiri: string.sub(s, 0, 3)
s = 'hello'
print(s.sub(0, 3))   -- 'hel'
----

This change affects all table constructors, `ipairs()` iteration, string functions and array access.  When migrating numeric `for` loops that iterate over tables, adjust the start index from 1 to 0 and the end condition accordingly.

[[sec-migration-method-calls]]
=== Method Calls and the Colon

indexterm:[Lua, method calls] indexterm:[colon syntax] Tiri has no colon call syntax and no `self` parameter.  A function called as a member of a table entity receives that table as its current context and reaches it through self referencing, so the receiver is neither declared nor passed.  See <<sec-the-current-context>>.

The context feature is opt-in.  A Lua table that carries methods becomes an entity by constructing it with the `entity` prefix, or by attaching a metatable that declares `pass:[__]context = true`.  Without designation the table remains ordinary and its methods observe the caller's context, not the receiver.  See <<sec-table-entities>>.

==== Calls

Replace `receiver:method(pass:[...])` with `receiver.method(pass:[...])`:

[source,tiri]
----
-- Lua
local upper = s:upper()
local parts = s:gsub('%s', '')

-- Tiri
upper = s.upper()
parts = s.replace(' ', '')
----

The dot form is not merely a rename.  For the built-in types -- `str`, `table`, `array`, `range`, `struct` and file handles -- `receiver.method(pass:[...])` invokes a registered built-in method and passes the receiver automatically, so it remains equivalent to the namespace form `string.upper(s)`.  See <<sec-built-in-method-calls>>.

==== Declarations

Replace `function t:name(pass:[...])` with a dot-qualified declaration, designate the receiver as an entity, and rewrite every `self.field` reference as `&field`.  A bare `self` becomes `+&&+`.  Call sites change only in the separator:

[source,tiri]
----
-- Lua
Account = {}
function Account:deposit(Amount)
   self.balance = self.balance + Amount
end
account:deposit(50)

-- Tiri
Account = entity { balance = 0 }
function Account.deposit(Amount:num)
   &balance += Amount
end
account.deposit(50)
----

The mapping from `self.` to `&`, and from `self` to `+&&+`, is direct, with four differences to check during migration:

- The receiver must be an __entity__.  An ordinary table inherits the caller's context instead of the receiver, so designate the table at the point where it is constructed.
- A function extracted from a table (`ref = t.handler`) carries no association with a receiver.  Pass the table and call the method on it, or wrap the call in a closure, when a receiver must survive the extraction; see <<sec-extracted-methods>>.
- A callback registered as a function value captures the context that is current at the point of registration, and observes that table on every invocation.  This covers framework callbacks and Tiri's own subscription interfaces -- `processing.delayedCall()`, `object.subscribe()`, `subscribeEvent()`, `input` and `async`.  See <<sec-context-and-callbacks>>.
- A function that must operate on a table other than its receiver declares that table as an ordinary parameter.

The `pass:[__]index` class pattern carries over apart from this substitution and the addition of `pass:[__]context = true` to the class table; see <<sec-class-pattern>>.

Lua's `setmetatable(t, mt)` is unrestricted.  In Tiri a metatable that designates an entity may only be attached to an allocation owned by the designating function, through a direct call to the built-in `setmetatable()`; see <<sec-context-metafield>>.

==== Method Names That Collide with Built-ins

A function assigned to a table member whose name matches a built-in `table` method is rejected at compile time, because the built-in owns the immediate call position.  Lua code that defines methods named `insert`, `remove`, `concat`, `clear`, `sort` or similar must be renamed, or declared with a computed key and called through one of the field-call escape forms.  See <<sec-built-in-method-calls>>.

[[sec-migration-scoping]]
=== Variable Scoping

In standard Lua, an undeclared variable is implicitly global.  In Tiri, assignments to undeclared names create locals, and reads of undeclared names are compile-time errors.  Use the `global` keyword to declare globals created by the script.  Use `extern` for symbols supplied by another parsed file or by the embedding host.

[source,tiri]
----
-- Lua
counter = 0              -- implicitly global
function inc()
   counter = counter + 1 -- accesses global
end

-- Tiri
global glCounter = 0     -- explicitly global
function inc()
   glCounter++           -- accesses global
end

extern hostValue
print(hostValue)         -- host-supplied global
----

The `local` keyword remains available for explicit scope control and multi-variable declarations.

[source,tiri]
----
local a, b, c = 1, 2, 3
----

Host-registered built-in names are protected from rebinding.  Replace a built-in name only by creating an explicit local shadow:

[source,tiri]
----
math = {}                -- error: protected built-in global
local math = {}          -- valid local shadow
----

See <<ch-variables-and-scoping>> for the full scoping rules, including `global`, `extern`, protected globals, and naming conventions.

[[sec-migration-exception-handling]]
=== Exception Handling

`pcall()` and `xpcall()` are removed.  Tiri provides structured exception handling through `try-except`:

[source,tiri]
----
-- Lua
local ok, err = pcall(function()
   risky_operation()
end)
if not ok then
   print('Error: ' .. err)
end

-- Tiri
try
   risky_operation()
except e
   print('Error: ' .. e.message)
end
----

`try-except` supports filtered handlers with the `when` clause to catch specific `ERR` codes, a `success` block that runs when no exception occurred, and optional stack trace capture with `try<trace>`.

The `io.*` library functions raise exceptions on error instead of returning error codes.  Replace code that checks return values from `io.open()` or `file.read()` with `try-except` blocks:

[source,tiri]
----
-- Lua
local file, err = io.open('data.txt', 'r')
if not file then
   print('Failed: ' .. err)
   return
end

-- Tiri
try
   file = io.open('data.txt', 'r')
except e
   print('Failed: ' .. e.message)
   return
end
----

See <<ch-error-handling>> for the complete exception handling reference, including `raise`, `check`, `error()` and filtered handlers.

[[sec-migration-control-flow]]
=== Control Flow Changes

[[sec-migration-numeric-for]]
[discrete]
==== Numeric For Loops

indexterm:[Lua, numeric for] The Lua numeric loop header `for Name = Start, Stop [, Step]` is removed.  Counted iteration is expressed with a range literal instead.  A numeric header raises a `DeprecatedSyntax` parse error that names the replacement form.

Lua's numeric loop is inclusive of `Stop`, so `{Start into Stop}` is the direct equivalent.  Use `{Start to Stop}` when the stop value is to be excluded, and the `by` clause in place of the third header expression:

[cols="2,3"]
|===
|Lua |Tiri

|`for i = 0, 9 do`
|`for i in {0 into 9} do` or `for i in {0 to 10} do`

|`for i = 1, 10, 2 do`
|`for i in {1 into 10 by 2} do`

|`for i = 10, 1, -1 do`
|`for i in {10 into 1} do`
|===

[source,tiri]
----
-- Lua
for i = 1, 10, 2 do
   print(i)
end

-- Tiri
for i in {1 into 10 by 2} do
   print(i)
end
----

Unlike the Lua header, the step direction is inferred from `Start` and `Stop`, so a descending range does not require a negative step.  See <<sec-range-for-loop>> and <<ch-ranges>>.

[discrete]
==== The goto Statement

The `goto` statement and `::label::` syntax are removed.  The constructs that `goto` is commonly used for in Lua are replaced by dedicated statements:

[cols="2,3"]
|===
|Lua Pattern |Tiri Replacement

|Skip to next iteration
|`continue`

|Break out of a loop
|`break`

|Cleanup before return
|`defer`
|===

[[sec-migration-coroutines]]
=== Coroutines

indexterm:[Lua, coroutines] indexterm:[coroutines] The `coroutine` library is removed and Tiri provides no coroutine type.  There is no direct replacement, because Tiri offers no mechanism for suspending and resuming a call stack.

Code that relies on coroutines is restructured according to the purpose the coroutine served:

[cols="2,3"]
|===
|Lua Pattern |Tiri Replacement

|Generator or custom iterator
|An iterator function that holds its state in a closure.  See <<sec-generic-for-loop>>.

|Deferring the evaluation of an expression
|Deferred expressions `<{ expr }>` and thunks.  See <<ch-resource-management>>.

|Concurrent or background work
|The `async` interface, which executes work on real threads against a Kōtuku object.  See <<ch-threading>>.

|Cooperative scheduling around I/O or events
|The event processing loop with `processing.sleep()`.  See <<ch-processing-and-events>>.
|===

A coroutine-based generator is rewritten as a closure that returns the next value on each call, which is the form the generic `for` loop consumes directly:

[source,tiri]
----
-- Lua
local function counter(Limit)
   return coroutine.wrap(function()
      for i = 1, Limit do coroutine.yield(i) end
   end)
end

-- Tiri
function counter(Limit)
   i = 0
   return () => do
      i++
      if i > Limit then return nil end
      return i
   end
end

for v in counter(5) do
   print(v)
end
----

Note that the `async` interface is not a substitute for coroutines in the general case.  Asynchronous work executes on a separate thread in an isolated script state and cannot share local variables with the caller, whereas a coroutine shares the enclosing scope.  See <<sec-threading-model>> for the constraints.

[[sec-migration-string-functions]]
=== String Function Changes

[discrete]
==== Index Migration Note

When migrating code that computes substring bounds dynamically, remember that Lua uses 1-based indices with an inclusive end, while Tiri uses 0-based indices with an exclusive end.  A direct translation is:

[source,tiri]
----
-- Lua
part = string.sub(s, Start, Stop)      -- Start/Stop are 1-based, Stop inclusive

-- Tiri
part = string.sub(s, Start - 1, Stop) -- Start is 0-based, Stop is exclusive
----

[discrete]
==== Removed Functions

The following Lua string functions are removed:

[cols="2,3"]
|===
|Function |Replacement

|`string.gsub()`
|`regex.new(Pattern).replace(Text, Replacement)` or `string.replace()` (literal only)

|`string.match()`
|`regex.new(Pattern).extract(Text)` or `regex.new(Pattern).findFirst(Text)`

|`string.gmatch()`
|`regex.new(Pattern).findAll(Text)`

|`string.find()` with patterns
|`regex.new(Pattern).findFirst(Text)` or `string.find()` (literal only)
|===

See <<sec-migration-pattern-matching>> for the pattern-to-regex migration guide.

[[sec-migration-pattern-matching]]
=== Migration from Lua Patterns
indexterm:[Lua, patterns] Lua patterns are deprecated in favour of ECMAScript-compatible regular expressions compiled with `regex.new()`.  The following table maps common Lua pattern constructs to their regex equivalents:

[cols="2,2,3"]
|===
|Lua Pattern |Regex Equivalent |Description

|`%a`
|`[a-zA-Z]` or `[[:alpha:]]`
|Letters

|`%d`
|`\d` or `[0-9]`
|Digits

|`%w`
|`\w` or `[a-zA-Z0-9_]`
|Alphanumeric characters

|`%s`
|`\s` or `[ \t\n\r\f\v]`
|Whitespace

|`%l`
|`[a-z]`
|Lower-case letters

|`%u`
|`[A-Z]`
|Upper-case letters

|`%p`
|`[[:punct:]]`
|Punctuation

|`%c`
|`[[:cntrl:]]`
|Control characters

|`.`
|`.`
|Any character (identical)

|`%b()`
|No direct equivalent
|Balanced match (use recursive patterns or manual parsing)
|===

Capitalised Lua pattern classes (e.g. `%A`, `%D`) represent the complement set.  In regex, use `[^pass:[...]]` or the capitalised shorthand (`\D`, `\W`, `\S`).

[discrete]
==== Quantifiers

[cols="2,2"]
|===
|Lua |Regex

|`*`  |`*`
|`+`  |`+`
|`-`  |`*?` (lazy)
|`?`  |`?`
|===

Lua's `-` quantifier (lazy match) maps to `*?` in regex.

[discrete]
==== Captures

Lua patterns use `()` for captures.  Regular expressions use the same syntax; in Tiri, prefer `rx.extract()` for `string.match()`-style capture extraction:

[source,tiri]
----
-- Lua
local year, month, day = string.match(date, '(%d+)-(%d+)-(%d+)')

-- Tiri
rx = regex.new([[(\d+)-(\d+)-(\d+)]])
year, month, day = rx.extract(date)
----

[discrete]
==== Anchors

Lua uses `^` and `$` for start-of-string and end-of-string anchors.  Regular expressions use the same anchors.

[discrete]
==== Common Migration Examples

[source,tiri]
----
-- Lua: strip whitespace
s = string.gsub(s, '^%s+', '')
s = string.gsub(s, '%s+$', '')

-- Tiri
s = s.trim()
-- Or with regex:
s = regex.new([[^\s+]]).replace(s, '')
s = regex.new([[\s+$]]).replace(s, '')
----

[source,tiri]
----
-- Lua: split on comma
for item in string.gmatch(csv, '([^,]+)') do
   process(item)
end

-- Tiri
items = csv.split(',')
for i, item in ipairs(items) do
   process(item)
end
----

[source,tiri]
----
-- Lua: replace all occurrences
result = string.gsub(text, 'old', 'new')

-- Tiri
result = text.replace('old', 'new')
-- Or with regex for pattern-based replacement:
result = regex.new([[pattern]]).replace(text, 'replacement')
----

See <<ch-regular-expressions>> and <<ch-strings>> for the complete API references.

[[sec-migration-removed-functions]]
=== Removed and Replaced Functions

The following standard Lua functions are removed or replaced:

[cols="2,3"]
|===
|Function |Replacement

|`loadstring(Code)`
|`exec(Code)` parses and executes `Code` immediately, returning any values produced.  Unlike `loadstring()`, it does not return a compiled function.

|`dofile(Path)`
|`loadFile(Path)` loads and executes a file.

|`select(N, pass:[...])`
|Result filter operator `[mask]`.  See <<ch-result-management>>.

|`unpack(Table)`
|Removed, with no replacement.  Use multiple assignment, or a result filter (<<ch-result-management>>) when selecting from the results of a call.

|`getfenv()` / `setfenv()`
|Removed.  Use `debug.getEnv()` and `debug.setEnv()`.  See <<sec-the-global-environment>>.

|`gcinfo()`
|Removed.  Use the garbage collector interface if memory reporting is needed.

|`table.maxn()`
|Removed.  Use `#t` for the length of a table or array, or `rawlen(t)` if the table also holds non-numeric keys.
|===

[discrete]
==== Behavioural Differences

Three constructs in common Lua code return different values in Tiri and produce no diagnostic when translated literally:

`#t` on a mixed table::
Lua returns the sequence length and ignores the hash part.  Tiri returns `nil` for any table that has ever been stored through a key that is not a positive integer.  Positive integer keys are unaffected however scattered, so `t[9999]` leaves the length intact.  Translate `#t` to `rawlen(t)` wherever the numerical sequence length is what the original code meant.  See <<sec-table-classification>>.

`type()` on a boolean::
Lua returns `'boolean'`, Tiri returns `'bool'.  A Lua test written as `type(v) is 'boolean'` therefore evaluates to `false` for every value.  See <<sec-type-inspection>>.

`math.random(N)`::
Lua returns an integer in [1, `N`].  Tiri returns an integer in [0, `N`), matching its zero-based indexing so that `math.random(#arr)` is a valid index.  Translate a one-based Lua call to the two-argument form `math.random(1, N)`.  See <<sec-random-numbers>>.

Two further differences produce an explicit diagnostic rather than a wrong value:

Sequence operations reject classified tables::
`table.insert()`, `table.remove()`, `table.sort()`, `table.slice()` and `table.concat()` without an explicit `End` require a table classified as a sequence, and raise an error otherwise.  Lua applies them to any table.  Where the original code inserts into a record-shaped table, assign through an explicit index instead, or supply `End` to `table.concat()`.  `table.kind()` reports the classification and `table.size()` counts every entry.

Duplicate constructor keys are rejected::
Lua accepts `{ name = 1, name = 2 }` and keeps the last value.  Tiri rejects any duplicate key it can resolve at compile time.  See <<sec-table-fundamentals>>.

[[sec-migration-removed-libraries]]
=== Removed Libraries

The following standard Lua libraries are removed because their functionality is provided by the Kōtuku framework:

[discrete]
==== Package Library

The `package` library (`require`, `module`, `package.path`, etc.) is removed.  Tiri provides `include` and `import` for script organisation.  See <<ch-script-management>>.

[source,tiri]
----
-- Lua
local json = require('json')

-- Tiri
import 'json' as json
----

[discrete]
==== OS Library

The `os` library is removed.  Time, date and filesystem operations are provided by Kōtuku classes:

[cols="2,3"]
|===
|Lua Function |Kōtuku Equivalent

|`os.time()`
|Kōtuku Time class

|`os.date()`
|Kōtuku Time class

|`os.clock()`
|Kōtuku Time class

[[sec-migration-arrays]]
=== Arrays as a Distinct Type
indexterm:[Lua, arrays] Lua uses tables for both associative maps and sequential data.  Tiri introduces arrays as a separate, performance-optimised type for sequential (integer-indexed) data.  Prefer arrays over tables when storing ordered, numerically indexed data.

[source,tiri]
----
-- Lua: sequential table
local items = { 'a', 'b', 'c' }
table.insert(items, 'd')

-- Tiri: use an array
items = array<str> { 'a', 'b', 'c' }
items.push('d')
----

Arrays are zero-indexed, support dedicated methods (`push`, `pop`, `map`, `filter`, `sort`, etc.) and offer better iteration performance than tables.  See <<ch-arrays>> for the complete API.

[[sec-migration-new-features]]
=== New Features with No Lua Equivalent

The following Tiri features have no counterpart in standard Lua.  They do not require migration but are available to improve code that was previously limited by Lua's feature set:

* **Compound assignment**: `+=`, `-=`, `*=`, `/=`, `%=`, `..=` (see <<ch-variables-and-scoping>>)
* **Postfix increment**: `counter++` (see <<ch-operators>>)
* **Arrow functions**: `n pass:[=>] n * 2` (see <<ch-functions>>)
* **String interpolation**: `f'Hello {name}'` (see <<sec-string-interpolation>>)
* **Safe navigation**: `obj?.field` (see <<ch-operators>>)
* **Ternary operator**: `cond ? a : b` (see <<ch-operators>>)
* **If-nil assignment**: `x ?= default` (see <<ch-operators>>)
* **If-empty operator**: `value ?? default` (see <<ch-operators>>)
* **If-empty assignment**: `x ??= default` (see <<ch-operators>>)
* **Ranges**: `{0 to 10}`, `{0 into 10}` (see <<ch-ranges>>)
* **Type annotations**: `local x:num = 0` (see <<ch-type-system>>)
* **Constant variables**: `local x <const> = 42` (see <<ch-variables-and-scoping>>)
* **Enum declarations**: `enum PREFIX { MEMBER, pass:[...] }` (see <<sec-enum-declarations>>)
* **External declarations**: `extern hostValue` (see <<sec-the-extern-keyword>>)
* **To-be-closed variables**: `resource <close> = pass:[...]` (see <<ch-resource-management>>)
* **Defer statement**: `defer pass:[...] end` (see <<ch-resource-management>>)
* **Choose expressions**: `choose x from pass:[...] end` (see <<ch-pattern-matching>>)
* **Result filter**: `[_*]func()` (see <<ch-result-management>>)
* **Pipe operator**: `x |> func()` (see <<ch-result-management>>)
* **Deferred expressions**: `<{ expr }>` (see <<ch-resource-management>>)
* **Thunk functions**: `thunk name():type pass:[...] end` (see <<ch-resource-management>>)
* **Metamethod literals**: `metamethod(pass:[...]) pass:[...] end` (see <<sec-metamethod-literals>>)
* **Unicode operator aliases**: see <<sec-unicode-operator-aliases>>
* **Approximate equality**: `a ≈ b` (see <<sec-approximate-equality>>)

The following subsections illustrate how selected features replace common verbose Lua patterns.  Each example shows the Lua idiom followed by the equivalent Tiri code.  Refer to the cross-referenced chapters for the complete specification.

[discrete]
==== If-Nil and If-Empty Assignment

The `?=` operator assigns a value only when the variable is `nil`.  The `??=` variant assigns when the variable is falsey under extended semantics (`nil`, `false`, `0`, `""`, or an empty collection).  Both replace the common Lua pattern of checking before assigning defaults.

[source,tiri]
----
-- Lua
function initialise(options)
   if options == nil then
      options = {}
   end
   if options.timeout == nil then
      options.timeout = 30
   end
end

-- Tiri
function initialise(Options)
   Options ?= {}
   Options.timeout ?= 30
end
----

[discrete]
==== Ternary Operator

The ternary operator `condition ? a : b` replaces four-line if-then-else blocks when selecting between two values.  Only the selected branch is evaluated.

[source,tiri]
----
-- Lua
local label
if count > 1 then
   label = 'items'
else
   label = 'item'
end

-- Tiri
label = count > 1 ? 'items' : 'item'
----

[discrete]
==== Safe Navigation

The `?.` operator short-circuits to `nil` when the left-hand side is `nil`, eliminating nested guard clauses.

[source,tiri]
----
-- Lua
local city = nil
if user ~= nil then
   if user.profile ~= nil then
      if user.profile.address ~= nil then
         city = user.profile.address.city
      end
   end
end

-- Tiri
city = user?.profile?.address?.city
----

The same safe-nav operators may also guard assignments:

[source,tiri]
----
user?.profile?.name = 'Guest'
user?.stats?.count += 1
user?.profile?.nickname ?= 'Anonymous'
user?.profile?.tag ??= 'new'
----

If a guarded hop is `nil`, that assignment is skipped.  For a single target, the RHS is not evaluated when the guarded store is skipped.

[discrete]
==== If-Empty Operator

The `??` operator returns the right-hand operand when the left-hand side is falsey under extended semantics.  Unlike Lua's `or`, it correctly handles `0` and `""` as falsey values.

[source,tiri]
----
-- Lua: the 'x and x or y' idiom fails when x is 0 or false
local width = opts.width or 100  -- broken if opts.width is 0

-- Tiri: ?? treats 0 and "" as falsey
width = opts.width ?? 100        -- correctly defaults when 0
name = user?.name ?? 'Guest'     -- combines with safe navigation
----

[discrete]
==== String Interpolation

Interpolated strings prefixed with `f` embed expressions directly, replacing long concatenation chains.

[source,tiri]
----
-- Lua
print('Hello, ' .. name .. '! You scored ' .. tostring(score) .. ' points.')

-- Tiri
print(f'Hello, {name}! You scored {score} points.')
----

[discrete]
==== Arrow Functions

Arrow functions provide concise syntax for anonymous functions, particularly useful with higher-order operations on arrays and ranges.

[source,tiri]
----
-- Lua
table.sort(items, function(a, b)
   return a.name < b.name
end)

-- Tiri
items.sort((a, b) => a.name < b.name)
----

[discrete]
==== Defer

The `defer` statement schedules cleanup code to run when the enclosing scope exits via normal completion, `return`, `break` or `continue`.  This replaces the Lua pattern of manually closing resources at every exit point.

IMPORTANT: `defer` blocks do *not* run during error unwinding.  A `pcall`-based Lua idiom that guarantees cleanup on error translates to a `<close>` variable, not to `defer`.  See <<sec-to-be-closed-variables>>.

[source,tiri]
----
-- Lua
function readConfig(path)
   local file, err = io.open(path, 'r')
   if not file then return nil, err end
   local ok, content = pcall(file.read, file, '*a')
   file.close()           -- must remember to close before every return
   if not ok then return nil, content end
   return content
end

-- Tiri
handle_mt = {
   __close = metamethod(Error)
      &file.close()
   end
}

function readConfig(Path)
   local cfg <close> = setmetatable({ file = io.open(Path, 'r') }, handle_mt)
   return cfg.file.read('*a')   -- closed on every outcome
end
----

A `<close>` variable is used here rather than `defer` because `io.open()` and `file.read()` raise exceptions, and `defer` does not run during error unwinding.  Use `defer` when cleanup only needs to cover normal exits, `return`, `break` and `continue`.  File handles returned by `io.open()` carry no `pass:[__]close` metamethod of their own, so the wrapper table above supplies one.

[discrete]
==== Ranges

Range literals replace manually constructed numeric `for` loops and support functional methods like `map`, `filter` and `reduce`.

[source,tiri]
----
-- Lua
local squares = {}
for i = 0, 9 do
   squares[i + 1] = i * i
end

-- Tiri
squares = {0 to 10}:map(i => i * i)
----
