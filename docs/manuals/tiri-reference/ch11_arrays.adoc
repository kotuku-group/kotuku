[[ch-arrays]]
== Arrays
indexterm:[arrays] indexterm:[typed arrays] Arrays are mutable, typed, contiguous sequences of elements.  Each array holds elements of a single declared type, providing efficient storage and direct memory access.  Arrays are a distinct type from tables, purpose-built for sequential data where all elements share a common type.

Arrays are reference types.  Assigning an array to another variable creates a second reference to the same underlying data, not a copy.

[source,tiri]
----
nums = array<int> { 10, 20, 30 }
print(nums[0])      -- 10
print(#nums)        -- 3
print(type(nums))   -- 'array'
----

All indexing is zero-based.  The `#` operator returns the element count.  Element access by index is O(1) and is optimised by the JIT compiler in hot paths.  The `ipairs()`, `pairs()`, and `values()` functions work identically on arrays and tables.

[[sec-uint8-versus-byte]]
[discrete]
==== The One-Byte Element Types Are Distinct

indexterm:[arrays, uint8] indexterm:[arrays, int8] indexterm:[arrays, byte arrays] Three element types occupy one byte: `byte` (with its alias `char`), `uint8` and `int8`.  They are distinct types and are never interchangeable.  Only `byte` and `char` declare a *byte array*, which carries the string behaviour defined throughout this chapter.  `array<uint8>` and `array<int8>` are numeric arrays and carry none of it.  `byte` and `uint8` store the range 0--255; `int8` stores the range −128--127.

No two of the three types are ever equal, and `copy()` between them is rejected, because an array source must declare the same element type as the destination.  A parameter or return annotation naming one of them accepts only that exact type; `array<byte>` does not satisfy `array<int8>`, and `array<int8>` does not satisfy `array<byte>`.

[source,tiri]
----
buf = array<byte> { 72, 105 }
tostring(buf)              -- 'Hi'

nums = array<uint8> { 72, 105 }
tostring(nums)             -- 'array<uint8, 2>'
nums.push('A')             -- error: incompatible element type
nums.copy(buf)             -- error: incompatible element type

signed = array<int8> { -128, 127 }
tostring(signed)           -- 'array<int8, 2>'
signed.push('A')           -- error: incompatible element type
----

NOTE: Use `byte` (or `char`) for text and binary buffers, `uint8` for unsigned numeric data that happens to be one byte wide, and `int8` for signed one-byte numeric data.

[[sec-element-storage-contract]]
[discrete]
==== Element Storage Contract

indexterm:[arrays, element storage] indexterm:[arrays, type safety] Every operation that writes an element applies the same contract.  A value is stored only if it matches the declared element type exactly.  Values are never converted between categories; a conversion that crosses categories must be written explicitly at the call site.

* Numeric and string element types accept their counterparts only.  Use `tonumber()` and `tostring()` for conversion.
* The `table`, `array` and `obj` element types accept only a value of that exact category.
* A `struct<Name>` element type accepts only instances of the same struct definition.  A different definition is rejected even when its field layout is identical.
* The `any` element type accepts every value.

The element type therefore behaves as a type contract on every write, applying the same identity rules as the runtime contracts defined in <<sec-runtime-type-contracts>>.

`nil` writes the empty value for the element type: zero for numeric elements, a cleared reference for `str`, `table`, `array` and `obj` elements, and `nil` for `any` elements.  The `struct<Name>` element type is the sole exception and rejects `nil`, because a struct element is stored by value and has no empty representation.

Byte arrays (`byte`, `char`) extend the contract for two operations: 

* `push()` also accepts strings and appends their characters
* `..=` automatically stringifies values, as for regular string types.

Neither extension applies to `uint8` or `int8` arrays, which are numeric; see <<sec-uint8-versus-byte>>.

[source,tiri]
----
nums = array<int> { 1, 2, 3 }
nums[0] = 4             -- 4
nums[0] = '4'           -- error: incompatible element type
nums[0] = tonumber('4') -- 4

names = array<str> { 'a' }
names.push(42)          -- error: incompatible element type
names.push(tostring(42))  -- '42'
----

[[sec-element-numeric-conversion]]
[discrete]
==== Numeric Conversion

indexterm:[arrays, numeric conversion] Storing a number in a numeric element type narrower than a double converts the value by the following rules.  The result is defined for every accepted value and does not vary between platforms.

* Integer element types truncate the value towards zero, then wrap modulo the width of the type.  The signed types (`int8`, `int16`, `int`, `int64`) wrap into two's complement range.  The unsigned types (`byte`, `uint8`, `uint16`, `uint`, `uint64`) wrap into the range 0 to 2^__N__^−1, where __N__ is the width of the type in bits; a negative value therefore wraps to the top of that range.
* Integer element types reject infinity and NaN with an out-of-range error.
* The `float` element type rejects a finite value whose magnitude exceeds the largest representable single-precision number (approximately 3.4×10^38^) with an out-of-range error.  Infinity and NaN are stored unchanged.  All other values are rounded to the nearest representable single-precision value.
* The `double` element type accepts every number, including infinity and NaN.

A rejected value leaves the target element at its previous value.

[source,tiri]
----
vals = array<int> { 1.9, -1.9, 3000000000, nil }
-- vals = {1, -1, -1294967296, 0}

bytes = array<byte> { 300, -1 }
-- bytes = {44, 255}

signed = array<int8> { 300, -1 }
-- signed = {44, -1}

words = array<uint16> { -1, 65536, 1.9 }
-- words = {65535, 0, 1}

vals[0] = math.huge   -- error: value out of range; vals[0] remains 1
----

[discrete]
==== Precision of Wide Integer Elements

indexterm:[arrays, uint64] A number is a double-precision value, so whole numbers are exact only up to 2^53^ (<<sec-numbers>>).  The `int64` and `uint64` element types store the full width of the type, but a value written from or read back into a number is subject to that limit.  A `uint64` element is read as the nearest representable double, and a written value beyond 2^53^ is rounded before it is stored.  `concat()` reports the stored value exactly, because it formats the element directly.

[source,tiri]
----
counters = array<uint64> { -1 }
counters.concat('', '%llu')   -- '18446744073709551615'
counters[0]                   -- 1.844674407371e+19 (nearest double)
----

[[sec-array-atomic-mutation]]
[discrete]
==== Atomic Mutation

indexterm:[arrays, atomic mutation] Operations that write more than one element validate every value against the element contract before any element is written.  If any value is rejected, the operation raises an error and the array retains its original length and contents; a partial write is never observable.  This guarantee covers multi-value `push()` and `insert()`, `fill()`, and `copy()` from a table.

[source,tiri]
----
arr = array<int> { 10, 20, 30 }
arr.push(40, {})   -- error: incompatible element type
#arr               -- 3; arr is unchanged
----

==== Type Inspection

[.api]`name = arr.type()`

Returns the element type of the array as a string, e.g. 'char', 'float'.

[source,tiri]
----
array<int>.type()            -- 'int'
array<float>.type()          -- 'float'
array<byte>.type()           -- 'char'
array<uint8>.type()          -- 'uint8'
array<int8>.type()           -- 'int8'
array<uint>.type()           -- 'uint'
array<array<str>>.type()     -- 'array'
array<struct<Vec>>.type()    -- 'struct'
----

[discrete]
==== Read-Only Arrays

[.api]`result = arr.readOnly()`

Returns `true` if the array is read-only.  Read-only arrays are produced by Kōtuku API calls that expose internal buffers.  Mutation methods raise an error when called on a read-only array.

[discrete]
==== Length and Equality

The `#` operator returns the current element count.  The `is` operator performs content equality comparison: two arrays are equal if they have the same element type, the same length, and identical contents.  This differs from tables, where `is` compares by identity.  See <<sec-comparison-operators>> for the rationale behind this deliberate asymmetry.

[source,tiri]
----
a = array<int> { 1, 2, 3 }
b = array<int> { 1, 2, 3 }
c = a

a is c   -- true  (same object — also same contents)
a is b   -- true  (distinct objects, but same type, length, and contents)
#a       -- 3

rawequal(a, b) -- false (identity comparison: distinct objects)
rawequal(a, c) -- true  (identity comparison: same object)
----

Equality rules depend on the element type:

[cols="1,3a",options="header"]
|===
|Element Category |Comparison Method

|Primitive (`byte`, `int8`, `int16`, `int`, `int64`, `uint8`, `uint16`, `uint`, `uint64`, `float`, `double`)
|Raw memory comparison of the underlying data.

|`str`
|Element-by-element string comparison (hash, length, then content).

|`obj`
|Element-by-element comparison of object UIDs.
|===

Arrays with different element types are never equal, even if the raw values are numerically equivalent.  Equality for `table` and `any` element types is not yet supported and raises an error.

NOTE: Content equality is O(n) in the array length.  For primitive element types, the comparison uses `memcmp` and is highly efficient.  For string and object arrays, each element is compared individually.  If reference identity is sufficient, use `rawequal(a, b)` which is O(1).

[discrete]
==== String Conversion

The `tostring()` function, `string.format('%s', ...)`, and f-string interpolation all invoke the array's string conversion metamethod.

For byte arrays (`byte`, `char`), conversion returns the raw bytes interpreted as a string, preserving embedded NUL bytes:

[source,tiri]
----
buf = array<byte> { 72, 101, 108, 108, 111 }
tostring(buf)        -- 'Hello'
f'{buf}'             -- 'Hello'

str_arr = array.new('Hello')
tostring(str_arr)    -- 'Hello'
----

For all other element types, conversion returns a descriptive summary of the form `array<__type__, __length__>`:

[source,tiri]
----
tostring(array<int> { 1, 2, 3 })      -- 'array<int, 3>'
tostring(array<str> { 'a', 'b' })     -- 'array<str, 2>'
tostring(array<double, 0>)            -- 'array<double, 0>'
----

[discrete]
==== String Concatenation

Byte arrays (`byte`, `char`) can be used with the `..` concatenation operator.  The array is converted to a string and concatenated with the other value.  The result is always a new string; neither operand is modified.

[source,tiri]
----
buf = array<char> { 72, 105 }
'Say: ' .. buf            -- 'Say: Hi'
buf .. ' there'           -- 'Hi there'
buf .. 123                -- 'Hi123'
buf .. array<byte> { 33 } -- 'Hi!'
----

Non-byte arrays (e.g. `int`, `str`, `table`) cannot be concatenated with `..` and raise an error.

[discrete]
==== In-Place Append with `..=`

When the target of a `..=` compound assignment is an array, the operator appends to the array in place instead of producing a new value.  The array is mutated and its length grows.  This differs from the `..` operator, which always produces a new string and never mutates its operands.

The appended representation depends on the array's element type:

* Byte arrays (`byte`, `char`) follow concatenation semantics.  A string operand contributes its bytes, preserving embedded NUL bytes; a number operand contributes its decimal text, identical to the conversion the `..` operator performs.
* All other array types append the operand as a single element of the array's element type.  A number is stored as a numeric element, not as text.  The operand must satisfy <<sec-element-storage-contract>>; an incompatible operand raises an error and the array is unchanged.

If the right operand is a function call or vararg, only its first value is appended.  The target is any assignable array reference, including a table or object field.  See <<sec-compound-assignment>> for the general rules governing compound assignment.

[source,tiri]
----
buf = array<char>
buf ..= 'Value = '   -- append 8 bytes
buf ..= 42           -- append '42' as decimal text
print(buf)           -- 'Value = 42'

nums = array<int> { 1, 2 }
nums ..= 3           -- append the element 3; nums = {1, 2, 3}
----

TIP: A byte array assembled with `..=` is the most efficient way to build a large string buffer.  Each append mutates the array in place and reuses spare capacity, avoiding the repeated allocation and copying that building a string with `..` in a loop incurs.  Recover the finished string with `tostring(buf)` or `buf.getString()`, or pass the array directly to functions that support character arrays.

[source,tiri]
----
buf = array<char>
for i, line in ipairs(lines) do
   buf ..= line
   buf ..= '\n'
end
text = tostring(buf)
----

[[sec-creating-arrays]]
=== Creating Arrays
[discrete]
==== Typed Syntax

indexterm:[arrays, creation] The `array<type>` syntax creates arrays with concise, declarative notation:

[source,tiri]
----
arr = array<int>                       -- empty array
arr = array<int, 5>                    -- 5 elements, zero-initialised
arr = array<int> { 10, 20, 30 }        -- 3 elements with values
arr = array<int, 10> { 1, 2, 3 }       -- 10 elements; first 3 set, rest zero
arr = array<str> { 'a', 'b', 'c' }     -- string array with values
----

When both a size and initial values are provided, the array is first populated with the values, then extended to the specified size.  Extended elements are zero-initialised for numeric types or `nil` for reference types.  If the number of values exceeds the size, the values take precedence.

The size expression accepts variables and function calls:

[source,tiri]
----
n = 8
buf = array<int, n>   -- 8 zero-initialised elements
----

The `array<type>` form is also the array type annotation, where it constrains a variable, parameter or result to arrays of that element type.  A size is not permitted in that position.  See <<sec-array-member-annotations>>.

==== array.new()

[.api]`arr = array.new(Size, Type)`

Creates an array of `Size` elements with the specified element `Type` string.  Raises an error if `Size` is negative.

[source,tiri]
----
arr = array.new(100, 'int')
arr = array.new(50, 'double')
----

A string argument creates a byte array initialised from the string's bytes:

[source,tiri]
----
arr = array.new('Hello')
arr.type()     -- 'char'
#arr           -- 5
arr[0]         -- 72 (ASCII 'H')
----

==== array.of()

[.api]`arr = array.of(Type, Value, pass:[...])`

Creates an array populated with the given values.  At least one value is required.  Each value must satisfy <<sec-element-storage-contract>> for `Type`; an incompatible value raises an error and no array is returned.

[source,tiri]
----
arr = array.of('str', 'google.com', 'kotuku.dev')
arr = array.of('int', 1, 2, 3, 4, 5)
----

NOTE: The typed syntax `array<int> { 1, 2, 3 }` is preferred over `array.of()` for readability.

[[sec-element-access]]
[%breakable]
=== Element Access
[discrete]
==== Indexing

indexterm:[arrays, element access] Elements are accessed by zero-based integer index.  Out-of-bounds reads and writes raise an error.  Negative indices are not supported.

[source,tiri]
----
arr = array<int> { 10, 20, 30 }
arr[0]    -- 10
arr[2]    -- 30
arr[3]    -- error: index out of bounds
arr[-1]   -- error: negative index
----

[discrete]
==== first() and last()

[.api]`value = arr.first()`

Returns the first element, or `nil` if the array is empty.

[.api]`value = arr.last()`

Returns the last element, or `nil` if the array is empty.

[discrete]
==== Iteration

Arrays support three iteration styles for use in `for` loops.

Direct iteration returns index-value pairs, following the general rule defined in <<sec-bare-collection-iteration>>:

[source,tiri]
----
arr = array<int> { 10, 20, 30 }
for i, v in arr do
   print(i, v)
end
----

A single loop variable binds the index rather than the element, because the index is the first value yielded.  Use `for _, v in arr` or `values(arr)` to iterate elements alone.

The `ipairs()`, `pairs()`, and `values()` functions also work on arrays with identical semantics to tables:

[source,tiri]
----
for i, v in ipairs(arr) do pass:[...] end
for i, v in pairs(arr) do pass:[...] end
for v in values(arr) do pass:[...] end
----

TIP: Direct iteration is preferred over the use of `ipairs()` and `pairs()`, which are supported to maintain seamless compatibility with tables.

[discrete]
==== Membership Testing

The `in` operator tests whether a value exists in an array:

[source,tiri]
----
arr = array<str> { 'red', 'green', 'blue' }
'green' in arr       -- true
'yellow' in arr      -- false

if 'red' in arr then
   print('found')
end
----

[[sec-mutation-methods]]
=== Mutation Methods
[discrete]
==== push()

[.api]`length = arr.push(Value, pass:[...])`

indexterm:[arrays, mutation] Appends one or more values to the end of the array.  Grows the array if necessary.  Returns the new length.  If called with no arguments, returns the current length without modification.

Each value must satisfy <<sec-element-storage-contract>>.  All values are validated before the first is appended, so a rejected value leaves the array unchanged as defined in <<sec-array-atomic-mutation>>.

For byte arrays (`byte`, `char`), string arguments are also accepted: the bytes of each string are appended in sequence, preserving embedded NUL bytes.  Integer arguments are appended as single bytes.  A single call may mix strings and integers.

[source,tiri]
----
arr = array<int>
arr.push(10)         -- returns 1
arr.push(20, 30)     -- returns 3

buf = array<char>
buf.push('Hello')     -- append 5 bytes; returns 5
buf.push(32, 'World') -- append a space and 5 bytes; returns 11
----

[discrete]
==== pop()

[.api]`value = arr.pop([Count])`

Removes and returns elements from the end of the array.  If `Count` is omitted, removes one element.  If `Count` exceeds the array length, removes all elements.  Returns `nil` for each element beyond the array's content.

[source,tiri]
----
arr = array<int> { 10, 20, 30 }
arr.pop()       -- returns 30; #arr is 2
arr.pop()       -- returns 20; #arr is 1

arr = array<int> { 1, 2, 3, 4, 5 }
a, b = arr.pop(2)   -- a=5, b=4; #arr is 3
----

Returns `nil` on an empty array.

[discrete]
==== insert()

[.api]`length = arr.insert(Index, Value, pass:[...])`

Inserts one or more values at `Index`, shifting subsequent elements to the right.  Returns the new length.  Raises an error if `Index` is negative or exceeds the current length.  If no values are provided, the array is unchanged.

Each value must satisfy <<sec-element-storage-contract>>.  All values are validated before any element is shifted, so a rejected value leaves the array unchanged as defined in <<sec-array-atomic-mutation>>.  Unlike `push()`, string arguments are not accepted by byte arrays.

[source,tiri]
----
arr = array<int> { 1, 2, 5 }
arr.insert(2, 3, 4)   -- arr = {1, 2, 3, 4, 5}
arr.insert(0, 0)      -- arr = {0, 1, 2, 3, 4, 5}
----

[discrete]
==== remove()

[.api]`length = arr.remove(Index, [Count])`

Removes `Count` elements starting at `Index`, shifting subsequent elements to the left.  `Count` defaults to 1.  If `Count` exceeds the number of elements from `Index` to the end, removes all remaining elements from `Index`.  Returns the new length.  Raises an error if `Index` is negative, at or beyond the current length, or if `Count` is negative.

[source,tiri]
----
arr = array<int> { 1, 2, 3, 4, 5 }
arr.remove(2)       -- arr = {1, 2, 4, 5}
arr.remove(1, 2)    -- arr = {1, 5}
----

[discrete]
==== fill()

[.api]`arr.fill(Value, [Start, Count])` +
[.api]`arr.fill(Value, Range)`

Sets elements to `Value`.  With no additional arguments, fills the entire array.  With `Start` and `Count`, fills `Count` elements beginning at `Start`.  With a range, fills the elements selected by the range (supports exclusive, inclusive, negative, and stepped ranges).  The range must be whole-numbered as defined in <<sec-range-index-requirement>>; a fractional range raises an error.

`Value` must satisfy <<sec-element-storage-contract>> and is validated before the first element is written, so a rejected value leaves the array unchanged.  Reference element types accept a reference, or `nil` to clear the selected elements.

[source,tiri]
----
arr = array<int, 10>
arr.fill(0)               -- zero-fill all elements
arr.fill(99, 2, 3)        -- arr[2..4] = 99
arr.fill(77, {2 into 5})  -- arr[2 into 5] = 77 (inclusive)
arr.fill(33, range.new(0, 10, false, 2))   -- every 2nd element

refs = array<table, 3>
refs.fill({ id = 1 })     -- every element references the same table
refs.fill(nil, 1, 2)      -- clears refs[1] and refs[2]
----

[discrete]
==== sort()

[.api]`arr.sort([Descending])` +
[.api]`arr.sort(ComparatorFn)`

Sorts the array in place.  The default order is ascending.  If `Descending` is `true`, sorts in descending order.  Supported for all numeric types, string arrays, and `any` arrays.

Alternatively, a comparator function can be provided.  The function receives two elements `(a, b)` and returns `true` if `a` precedes `b` in the sorted result.  This works for all pushable array types, including `table` and `obj` arrays.

[source,tiri]
----
arr = array<int> { 5, 3, 1, 4, 2 }
arr.sort()        -- {1, 2, 3, 4, 5}
arr.sort(true)    -- {5, 4, 3, 2, 1}

-- Custom comparator: sort by absolute value
nums = array<int> { -5, 3, -1, 4, -2 }
nums.sort((a, b) => math.abs(a) < math.abs(b))

-- Sort tables by a field
people = array<table> {
   { name = 'Charlie', age = 35 },
   { name = 'Alice',   age = 28 },
   { name = 'Bob',     age = 31 }
}
people.sort((a, b) => a.age < b.age)  -- sorted by age ascending
----

[discrete]
==== reverse()

[.api]`arr.reverse()`

Reverses the order of all elements in place.

[source,tiri]
----
arr = array<int> { 1, 2, 3, 4, 5 }
arr.reverse()   -- {5, 4, 3, 2, 1}
----

[discrete]
==== clear()

[.api]`arr.clear()`

Resets the array length to zero.  Storage capacity is preserved for reuse.

[source,tiri]
----
arr = array<int> { 1, 2, 3 }
arr.clear()
#arr            -- 0
arr.push(67)    -- reuses existing capacity
----

[discrete]
==== resize()

[.api]`arr.resize(NewSize)`

Changes the array length to `NewSize`.  When growing, new elements are zero-initialised (or `nil` for reference types).  When shrinking, excess elements are discarded.  Raises an error if `NewSize` is negative.

[[sec-search-and-query]]
=== Search & Query
[discrete]
==== find()

[.api]`index = arr.find(Value, [Start], [Stop])` +
[.api]`index = arr.find(Value, Range)`

indexterm:[arrays, searching] indexterm:[arrays, querying] Searches for `Value` and returns its zero-based index, or `nil` if not found.  With a numeric `Start`, the search begins at that index.  `Stop` bounds the search as a half-open span `[Start, Stop)`, defaulting to the array length: the element at `Stop` is not examined.  A negative `Stop` is resolved against the array length, a `Stop` beyond the length is clamped to the length, and a span in which `Stop` is not greater than `Start` returns `nil`.

With a range, the search is restricted to the indices selected by the range (supports exclusive, inclusive, negative, stepped, and reverse ranges).  The range must be whole-numbered as defined in <<sec-range-index-requirement>>; a fractional range raises an error.

For `obj` arrays, `Value` can be an object or a numeric UID.

[source,tiri]
----
arr = array<int> { 10, 20, 30, 40, 50 }
arr.find(30)           -- 2
arr.find(30, 3)        -- nil (search starts at index 3)
arr.find(30, 0, 2)     -- nil (index 2 lies outside the span)
arr.find(30, 0, 3)     -- 2
arr.find(50, 0, #arr)  -- 4 (a stop equal to the length includes the last element)
arr.find(30, {0 to 5}) -- 2
arr.find(99)           -- nil
----

Reverse ranges search from higher to lower indices, finding the last occurrence first:

[source,tiri]
----
arr = array<int> { 10, 20, 30, 20, 40 }
arr.find(20, {4 into 0})   -- 3 (found searching backwards)
----

[[sec-copying-and-slicing]]
=== Copying & Slicing
[discrete]
==== clone()

[.api]`copy = arr.clone()`

indexterm:[arrays, copying] indexterm:[arrays, slicing] Creates a new array with the same element type and a copy of all elements.  For reference types (tables, objects, arrays), the clone is shallow: the new array holds references to the same underlying objects.

A `struct` element type is not supported and raises an error.

[discrete]
==== slice()

[.api]`result = arr.slice(Range)`

Returns a new array containing the elements selected by `Range`.  The result has the same element type as the source.  Supports exclusive, inclusive, negative, reverse, and stepped ranges.  Out-of-bounds indices are clamped.  The range must be whole-numbered as defined in <<sec-range-index-requirement>>; a fractional range raises an error.

[source,tiri]
----
arr = array<int> { 0, 10, 20, 30, 40, 50 }
arr.slice({1 to 4})       -- array<int> {10, 20, 30}
arr.slice({-2 into -1})   -- array<int> {40, 50}  (inclusive)
arr.slice({-2 to -1})     -- array<int> {40}      (exclusive)
arr.slice({4 into 2})     -- array<int> {40, 30, 20} (reverse)

arr.slice({0 to 6 by 2})   -- array<int> {0, 20, 40}
----

[discrete]
==== copy()

[.api]`arr.copy(Source, [DestIndex, SrcIndex, Count])`

Copies data into the array from `Source`.  `Source` can be an array, a string (copied as bytes into a byte array), or a table.

`DestIndex` specifies the starting position in the destination (default: 0).  `SrcIndex` specifies the starting position in the source (default: 0).  `Count` limits the number of elements copied (default: all remaining from `SrcIndex`).

Raises an error if the copy would exceed the destination bounds.

The source must match the destination:

* An array source must declare the same element type as the destination.  Element values are transferred without conversion, so an `array<double>` cannot be copied into an `array<int>`.
* A string source requires a byte array destination.
* A table source is read as a sequence and each element must satisfy <<sec-element-storage-contract>>.  The complete sequence is validated before the destination is modified, so a rejected element leaves the destination unchanged as defined in <<sec-array-atomic-mutation>>.

CAUTION: An array source is matched on its element type alone.  For a `struct` element type the struct definition is not compared, so two `struct` arrays declaring different definitions satisfy the check and their raw bytes are transferred.  The result is meaningless when the definitions differ, and unsafe when their sizes differ.  Confirm the definitions match at the call site before copying between struct arrays.

[source,tiri]
----
dest = array<int, 6>
dest.fill(0)
dest.copy(array<int> { 100, 200, 300 }, 2, 0, 3)
-- dest = {0, 0, 100, 200, 300, 0}

dest.copy({ 1.9, 2.1, 3.8 })
-- dest = {1, 2, 3, 200, 300, 0}

dest.copy({ 8, {}, 9 })   -- error: incompatible element type; dest is unchanged

buf = array<byte, 10>
buf.copy('Hello')
buf.getString(0, 5)   -- 'Hello'
----

[discrete]
==== table()

[.api]`t = arr.table()`

Converts the array to a table.  Each element becomes a sequential entry in the returned table.

[source,tiri]
----
arr = array<int> { 10, 20, 30 }
t = arr.table()
t[0]   -- 10
t[1]   -- 20
----

[discrete]
==== Byte Array String Methods

These methods are available only on byte (`char`) arrays.

[.api]`str = arr.getString([Start, Length])`

Extracts a string from the byte array starting at `Start` (default: 0) with the specified `Length` (default: remaining bytes from `Start`).  Raises an error if the range exceeds the array bounds, or if `Start` or `Length` is negative.

[.api]`count = arr.setString(String, [Start])`

Copies the bytes of `String` into the array at `Start` (default: 0).  If the string extends beyond the array bounds, it is clamped.  Returns the number of bytes written.

[source,tiri]
----
arr = array.new('Hello World')
arr.getString(0, 5)   -- 'Hello'
arr.getString(6)      -- 'World'

arr.setString('Greet', 0)
arr.getString(0, 5)   -- 'Greet'
----

[discrete]
==== concat()

[.api]`str = arr.concat([Separator], [Format], [Start], [Stop])`

Concatenates array elements into a string.  `Separator` is inserted between each element (default: empty string).  `Format` is an optional C-style format specifier applied to each element (e.g. `'%d'`, `'%.2f'`, `'%s'`).  `Start` and `Stop` are optional zero-based indexes that restrict the operation to the half-open span `[Start, Stop)` of the array.  `Stop` is exclusive, so `Stop - Start` elements are concatenated.  `Start` defaults to `0` and `Stop` defaults to the array length.

When `Format` is provided, it must contain exactly one format specifier.  An error is raised if `Format` contains zero or multiple specifiers, or if the format specifier is incomplete.  For non-string arrays without a format specifier, elements are converted to their default string representation, which is a more optimal conversion path.  Unsigned elements are converted to unsigned decimal text on that path.

An unsigned array constrains the permitted conversion, because the element is passed to the formatter at its own width:

* `uint8`, `uint16` and `uint` arrays require an unsigned conversion (`%u`, `%o`, `%x` or `%X`) with no length modifier.
* `uint64` arrays require one of the same conversions with the `ll` length modifier, e.g. `%llu` or `%llx`.

Every other conversion, including `%d` and `%s`, raises an error.

Concatenation is only available for primitive array types that consist of string and number elements.  Attempting to concatenate table, struct or object elements raises an error.

An error is raised if `Start` or `Stop` is negative, or greater than the array length.  A `Stop` equal to the array length is valid and selects through to the final element.  If `Stop` is not greater than `Start`, an empty string is returned; this includes an explicit `0, 0` span on an empty array.  Empty arrays are converted to an empty string.

[source,tiri]
----
arr = array<str> { 'hello', 'world' }
arr.concat(' ')          -- 'hello world'
arr.concat()             -- 'helloworld'

arr = array<int> { 1, 2, 3 }
arr.concat('-')          -- '1-2-3'

arr = array<int> { 10, 20, 30 }
arr.concat(', ', '%d')   -- '10, 20, 30'

arr = array<float> { 1.5, 2.7 }
arr.concat(' | ', '%.1f')   -- '1.5 | 2.7'
----

Unsigned arrays:

[source,tiri]
----
arr = array<uint8> { 1, 255 }
arr.concat(',')             -- '1,255'
arr.concat(',', '%u')       -- '1,255'
arr.concat(',', '%02x')     -- '01,ff'
arr.concat(',', '%d')       -- error: unsigned format required

wide = array<uint64> { 255 }
wide.concat('', '%llu')     -- '255'
wide.concat('', '%llX')     -- 'FF'
wide.concat('', '%u')       -- error: unsigned long long format required
----

Sub-range concatenation with `Start` and `Stop`:

[source,tiri]
----
arr = array<str> { 'a', 'b', 'c', 'd' }
arr.concat(',', nil, 1, 3)      -- 'b,c'
arr.concat(',', nil, 0, #arr)   -- 'a,b,c,d'
arr.concat(',', nil, 2, 2)      -- '': an empty span

arr = array<int> { 1, 2, 3, 4 }
arr.concat('-', '%02d', 1, 4)   -- '02-03-04'
----

[[sec-functional-methods]]
=== Functional Methods
indexterm:[arrays, functional methods] All functional methods in this section accept a callback function that receives `(Value, Index)` as parameters.  The `Index` parameter is optional; callbacks that only need the value can omit it.

[discrete]
==== each()

[.api]`arr.each(Callback)`

Calls `Callback(Value, Index)` for every element.  Returns the array for chaining.

[source,tiri]
----
arr = array<int> { 10, 20, 30 }
arr.each(function(v, i)
   print(i, v)
end)
----

[discrete]
==== map()

[.api]`result = arr.map(Callback)`

Returns a new array where each element is the result of `Callback(Value, Index)`.  The original array is not modified.  The result array preserves the source element type, including the struct definition of a `struct` element type.

Each callback result must satisfy <<sec-element-storage-contract>> for that element type; a result of another category raises an error.  Use `map()` for transformations that preserve the element type, and build a new array of the target type for transformations that do not.

[source,tiri]
----
arr = array<int> { 1, 2, 3, 4, 5 }
doubled = arr.map(v => v * 2)
-- doubled = {2, 4, 6, 8, 10}

arr.map(v => tostring(v))   -- error: incompatible element type
----

[discrete]
==== filter()

[.api]`result = arr.filter(Predicate)`

Returns a new array containing only the elements for which `Predicate(Value, Index)` returns a truthy value.  The original array is not modified.  The result declares the same element type as the source.

A `struct` element type is not supported, because the result array is created without the struct definition that gives a struct element its size.  Filter a `struct` array by iterating it and appending the wanted elements to an array constructed with the same `array<struct<Name>>` declaration.

[source,tiri]
----
arr = array<int> { 1, 2, 3, 4, 5, 6 }
evens = arr.filter(v => v % 2 is 0)
-- evens = {2, 4, 6}
----

[discrete]
==== reduce()

[.api]`result = arr.reduce(Initial, Reducer)`

Applies `Reducer(Accumulator, Value, Index)` to each element, threading the accumulator from left to right.  Returns the final accumulator.  If the array is empty, returns `Initial` unchanged.

[source,tiri]
----
arr = array<int> { 1, 2, 3, 4, 5 }
sum = arr.reduce(0, (acc, v) => acc + v)
-- sum = 15

product = arr.reduce(1, (acc, v) => acc * v)
-- product = 120
----

[discrete]
==== any()

[.api]`result = arr.any(Predicate)`

Returns `true` if `Predicate(Value, Index)` returns a truthy value for at least one element.  Returns `false` on an empty array.

[source,tiri]
----
arr = array<int> { 1, 3, 5, 6, 7 }
arr.any(v => v % 2 is 0)   -- true
----

[discrete]
==== all()

[.api]`result = arr.all(Predicate)`

Returns `true` if `Predicate(Value, Index)` returns a truthy value for every element.  Returns `true` on an empty array (vacuous truth).

[source,tiri]
----
arr = array<int> { 2, 4, 6, 8 }
arr.all(v => v % 2 is 0)   -- true
----

[discrete]
==== Chaining

Functional methods that return arrays can be chained:

[source,tiri]
----
arr = array<int> { 1, 2, 3, 4, 5 }

result = arr.map(v => v * 2).filter(v => v > 5)
-- result = {6, 8, 10}

sum = arr.filter(v => v % 2 is 0)
   :reduce(0, (acc, v) => acc + v)
-- sum = 6
----
