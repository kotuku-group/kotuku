[[ch-metatables-and-metamethods]]
== Metatables & Metamethods
indexterm:[metatables] indexterm:[metamethods] A metatable is a regular table that the runtime attaches to another table or userdata to customise its behaviour.  When an operation has no native implementation for a given operand -- for example, adding two tables -- the runtime looks up a specially named field in the operand's metatable.  If the field exists and holds a callable value, the runtime invokes it.  That callable value is called a _metamethod_.

Every table and full userdata can carry exactly one metatable.  Strings share a single metatable provided by the string library.  Numbers, booleans, and `nil` do not carry per-value metatables, but the runtime can attach shared base metatables to non-table values via `debug.setMetatable`.

[[sec-metatable-basics]]
=== Metatable Basics
==== Setting and Querying

[.api]`table = setmetatable(Table, Metatable)`

indexterm:[metatables, basics] Sets the metatable of `Table` to `Metatable` and returns `Table`.  Pass `nil` as the second argument to remove the metatable entirely.  Raises an error if `Table` already carries a metatable that defines a `pass:[__]metatable` field.

[source,tiri]
----
mt = { __index = function(self, key) return 0 end }
t = setmetatable({}, mt)
----

[.api]`mt = getmetatable(Table)`

Returns the metatable of `Table`, or `nil` if none is set.  If the metatable defines a `pass:[__]metatable` field, returns the value of that field instead of the actual metatable.

A metatable can be replaced at any time by calling `setmetatable` again, provided the current metatable does not define `pass:[__]metatable`.

==== Metatable Protection

Setting a `pass:[__]metatable` field on a metatable achieves two effects:

- `getmetatable` returns the value of the `pass:[__]metatable` field rather than the real metatable.
- `setmetatable` raises an error, preventing replacement or removal of the metatable.

[source,tiri]
----
mt = { __metatable = 'locked' }
t = setmetatable({}, mt)
print(getmetatable(t))    -- 'locked'
-- setmetatable(t, nil)   -- raises error: cannot change a protected metatable
----

To bypass metatable protection for debugging purposes, use `debug.getMetatable` and `debug.setMetatable` (see <<ch-the-debug-library>>).

==== Raw Access

The following functions bypass all metamethods and operate directly on the underlying table data.  See <<sec-raw-access>> for full documentation.

[cols="2,4a",options="header"]
|===
|Function |Effect

|`rawget(Table, Key)`      |Returns the value at `Key` without invoking `pass:[__]index`.
|`rawset(Table, Key, Value)` |Sets `Key` to `Value` without invoking `pass:[__]newindex`.  Returns `Table`.
|`rawlen(Table)`           |Returns the raw length of the array part without invoking `pass:[__]len`.
|`rawequal(A, B)`          |Compares `A` and `B` by identity without invoking `pass:[__]eq`.
|===

Raw access suppresses metamethod dispatch, not the global environment policy.  A `rawset()` into a global environment is still validated for protected names and global type contracts, and a `pass:[__]newindex` metamethod installed on a global environment still receives non-raw stores.

[[sec-arithmetic-metamethods]]
=== Arithmetic Metamethods
indexterm:[metamethods, arithmetic] When an arithmetic operator encounters a non-numeric operand that cannot be coerced from a string, the runtime searches for the corresponding metamethod.  It checks the left operand's metatable first; if no metamethod is found there, it checks the right operand's metatable.  If neither operand provides the metamethod, the runtime raises an error.

[cols="2,2,3a",options="header"]
|===
|Operator |Syntax |Metamethod

|Addition       |`a + b`  |`pass:[__]add(a, b)`
|Subtraction    |`a - b`  |`pass:[__]sub(a, b)`
|Multiplication |`a * b`  |`pass:[__]mul(a, b)`
|Division       |`a / b`  |`pass:[__]div(a, b)`
|Modulo         |`a % b`  |`pass:[__]mod(a, b)`
|Exponentiation |`a ** b` |`pass:[__]pow(a, b)`
|Unary negation |`-a`     |`pass:[__]unm(a)`
|===

The runtime attempts string-to-number coercion before metamethod lookup.  If a string operand represents a valid number, the operation proceeds as a numeric computation and no metamethod is invoked.

See <<sec-arithmetic-operators>> for full operator semantics.

[source,tiri]
----
Vec2 = {}
Vec2.__index = Vec2

function Vec2.new(X, Y)
   return setmetatable({ x = X, y = Y }, Vec2)
end

Vec2.__add = function(A, B) return Vec2.new(A.x + B.x, A.y + B.y) end
Vec2.__sub = function(A, B) return Vec2.new(A.x - B.x, A.y - B.y) end
Vec2.__mul = function(A, B)
   if type(B) is 'number' then return Vec2.new(A.x * B, A.y * B) end
   return Vec2.new(A.x * B.x, A.y * B.y)
end
Vec2.__unm = function(A) return Vec2.new(-A.x, -A.y) end

v = Vec2.new(1, 2) + Vec2.new(3, 4)   -- Vec2(4, 6)
----

[[sec-comparison-and-equality]]
=== Comparison & Equality
==== Equality

indexterm:[metamethods, comparison] The `is` operator compares tables and userdata by identity.  Two distinct objects are never equal unless a `pass:[__]eq` metamethod overrides the comparison.

The runtime invokes `pass:[__]eq` only when both operands share the same metatable, or when both metatables define the same function object as their `pass:[__]eq` field.  If neither condition holds, the operator falls back to identity comparison.

The `is not` and `!=` operators negate the result of the `is` comparison, including any `pass:[__]eq` metamethod invocation.

`rawequal(A, B)` bypasses `pass:[__]eq` entirely and always compares by identity.

==== Ordering

[cols="2,2,3a",options="header"]
|===
|Operator |Syntax |Metamethod

|Less than          |`a < b`  |`pass:[__]lt(a, b)`
|Less than or equal |`a <= b` |`pass:[__]le(a, b)`
|Greater than       |`a > b`  |`pass:[__]lt(b, a)` (swapped operands)
|Greater than or equal |`a >= b` |`pass:[__]le(b, a)` (swapped operands)
|===

If `pass:[__]le` is absent but `pass:[__]lt` is defined, the runtime evaluates `a <= b` as `not (b < a)`.

For two string operands, the runtime performs a direct lexicographic comparison without consulting metamethods.  See <<sec-comparison-operators>> for full details.

[[sec-string-and-length]]
=== String & Length

==== __tostring

[.api]`pass:[__]tostring(Self)`

The `tostring` function and string interpolation invoke the `pass:[__]tostring` metamethod when one is present.  The return value becomes the string representation of the object.

[source,tiri]
----
mt = {
   __tostring = function(Self)
      return f'Point({Self.x}, {Self.y})'
   end
}
p = setmetatable({ x = 10, y = 20 }, mt)
print(tostring(p))   -- 'Point(10, 20)'
----

==== __concat

[.api]`pass:[__]concat(A, B)`

The `..` operator invokes `pass:[__]concat` when either operand is neither a string nor a number.  The runtime checks the left operand's metatable first, then the right operand's metatable.  See <<sec-string-concatenation>>.

==== __len

[.api]`pass:[__]len(Self)`

The `#` operator invokes `pass:[__]len` when present on the operand's metatable, overriding the default table length.  The metamethod receives the table as its sole argument and returns the custom length.

[source,tiri]
----
mt = { __len = function(Self) return Self.size end }
t = setmetatable({ size = 42 }, mt)
print(#t)   -- 42
----

See <<sec-length-operator>> for full operator semantics.

[[sec-indexing]]
=== Indexing
==== __index

indexterm:[metamethods, indexing] The runtime invokes `pass:[__]index` when a table lookup finds no value for the given key.  Direct entries in the table always take precedence; the metamethod is consulted only for absent keys.

**Function form**.  When `pass:[__]index` is a function, the runtime calls it with the table and the key as arguments.  The return value becomes the result of the lookup.

[source,tiri]
----
mt = {
   __index = function(Self, Key)
      return f'default({Key})'
   end
}
t = setmetatable({ x = 1 }, mt)
print(t.x)   -- 1
print(t.y)   -- 'default(y)'
----

**Table form**.  When `pass:[__]index` is a table, the runtime repeats the lookup in that table.  This chaining continues through successive metatables, forming an inheritance hierarchy.  The chain is limited to a fixed depth to prevent infinite loops.

[source,tiri]
----
defaults = { colour = 'red', size = 10 }
mt = { __index = defaults }
t = setmetatable({}, mt)
print(t.colour)   -- 'red'
----

==== __newindex

The runtime invokes `pass:[__]newindex` when assigning to a key that does not already exist in the table.  Assignments to existing keys bypass the metamethod and modify the table directly.

**Function form**.  When `pass:[__]newindex` is a function, the runtime calls it with the table, the key, and the value.  The function is responsible for storing the value if desired.

[source,tiri]
----
mt = {
   __newindex = function(Self, Key, Value)
      error(f'read-only table: cannot set {Key}')
   end
}
t = setmetatable({ x = 1 }, mt)
t.x = 2   -- succeeds: existing key bypasses __newindex
t.y = 3   -- raises error: 'read-only table: cannot set y'
----

**Table form**.  When `pass:[__]newindex` is a table, the runtime redirects the assignment to that table instead.

Use `rawset` inside a `pass:[__]newindex` function to store values directly in the table without triggering recursion.

==== Proxy Pattern

A proxy table uses an empty table as the public interface and stores all data in a hidden backing table.  Both `pass:[__]index` and `pass:[__]newindex` redirect operations to the backing table, allowing the proxy to intercept every access and assignment.

[source,tiri]
----
function create_proxy(Backing)
   proxy = {}
   mt = {
      __index = Backing,
      __newindex = Backing
   }
   return setmetatable(proxy, mt)
end
----

==== Class Pattern

The `pass:[__]index` metamethod enables a simple class/inheritance pattern.  Setting a table's `pass:[__]index` to a class table causes method lookups on instances to fall through to the class.

[source,tiri]
----
Animal = {}
Animal.__index = Animal

function Animal.new(Name)
   return setmetatable({ name = Name }, Animal)
end

function Animal:speak()
   return f'{self.name} speaks'
end
----

[[sec-callable-tables]]
=== Callable Tables
[.api]`pass:[__]call(Self, ...)`

indexterm:[callable tables] The runtime invokes `pass:[__]call` when a table is used in a function-call expression.  The table itself is passed as the first argument, followed by the call arguments.  The metamethod may return any number of values.

[source,tiri]
----
Counter = {}
Counter.__index = Counter

function Counter.new(Start)
   return setmetatable({ count = Start ?? 0 }, Counter)
end

Counter.__call = function(Self)
   Self.count++
   return Self.count
end

c = Counter.new(0)
print(c())   -- 1
print(c())   -- 2
----

The `pass:[__]call` metamethod enables factory and constructor patterns where a table acts as both a namespace and a callable constructor.

[[sec-garbage-collection]]
=== Garbage Collection
==== __gc

[.api]`pass:[__]gc(Self)`

indexterm:[metamethods, garbage collection] indexterm:[finalisers] The `pass:[__]gc` metamethod is a _finaliser_.  The garbage collector invokes it with the object as its only argument when that object is about to be reclaimed.  Tables and full userdata both support finalisers.  Any return value is discarded.

Finalisation is nondeterministic.  The collector determines when an unreachable object is reclaimed, so a finaliser runs at an unspecified point after the last reference to the object is released, and possibly not until the interpreter shuts down.  Code that requires cleanup at a known point in the program must use `<close>` or `defer` instead; see <<sec-finalisers-and-scope-cleanup>>.

===== Registration

An object acquires a finaliser only at the moment a metatable that *already contains* a `pass:[__]gc` field is attached to it.  Adding `pass:[__]gc` to a metatable after that metatable has been attached does not register any object that is already using it.

[source,tiri]
----
-- Registered: __gc is present when the metatable is attached.
resource = setmetatable({}, { __gc = function(Self) print('released') end })

-- Not registered: __gc is added after attachment.
mt = {}
ignored = setmetatable({}, mt)
mt.__gc = function() print('never called') end
----

Attaching the metatable again registers the object, because the field is present at the time of that call:

[source,tiri]
----
mt = {}
subject = setmetatable({}, mt)
mt.__gc = function() print('released') end
setmetatable(subject, mt)   -- subject is now registered
----

`setmetatable()` accepts tables only.  A full userdata receives its metatable through `debug.setMetatable()`, which obeys the same rule:

[source,tiri]
----
debug.setMetatable(handle, { __gc = function(Self) print('released') end })
----

Registration is permanent for the lifetime of the object and cannot be cancelled.  Whether a call takes place is decided at finalisation time by looking up `pass:[__]gc` in the object's current metatable, so removing the field, or detaching the metatable, suppresses the call:

[source,tiri]
----
mt = { __gc = function() print('released') end }
subject = setmetatable({}, mt)
setmetatable(subject, nil)   -- no finaliser call takes place
----

===== One-Shot Finalisation

Every object is finalised at most once.  After its finaliser returns, the object is no longer eligible for finalisation, and attaching a further `pass:[__]gc` metatable does not re-arm it.  When the object next becomes unreachable it is reclaimed without any additional call.

The object is fully intact for the duration of the call.  Its fields, its metatable, and every value reachable from it can be read and written normally.

===== Resurrection

indexterm:[resurrection] A finaliser that stores its argument in a location that is still reachable makes the object reachable again.  The collector does not reclaim a resurrected object, and the object remains usable:

[source,tiri]
----
registry = nil

pending = setmetatable({ id = 1 }, {
   __gc = function(Self) registry = Self end   -- resurrects Self
})
pending = nil

processing.collect('full')
print(registry.id)   -- 1
----

Resurrection does not restore eligibility for finalisation.  One-shot semantics apply to the resurrected object, so releasing `registry` above reclaims the table silently.

===== Errors

An error raised by a finaliser is contained by the collector.  The error is reported as a runtime warning and collection proceeds to the next pending object.  It does not propagate to the code that triggered the collection, and it does not disturb any `try` block that is active at that point.

===== Ordering and Shutdown

Finalisers for objects reclaimed in the same collection cycle run in reverse order of registration.  No ordering relationship exists between objects reclaimed in different cycles.

Every registered object is finalised when the interpreter shuts down, in reverse order of registration, whether or not the object is still reachable.  Objects registered by a finaliser during shutdown are not finalised in that shutdown.

==== __mode

The `pass:[__]mode` field (not a callable metamethod) controls weak-reference behaviour for a table.  The value is a string containing one or both of the characters `k` and `v`:

[cols="1,4a",options="header"]
|===
|Mode |Effect

|`'k'`  |Weak keys.  An entry is removed when its key is collected by the garbage collector.
|`'v'`  |Weak values.  An entry is removed when its value is collected by the garbage collector.
|`'kv'` |Both keys and values are weak.
|===

The garbage collector reads `pass:[__]mode` from the metatable; it is not invoked as a function.

[source,tiri]
----
cache_mt = { __mode = 'v' }
cache = setmetatable({}, cache_mt)
----

===== Collectable Keys and Values

Weakness applies only to values that the garbage collector manages as objects: tables, arrays, functions, objects, structs and full userdata.  Strings, numbers, booleans and `nil` are not collectable and are never removed from a weak table.

This distinction determines whether a weak table releases anything at all.  A table with weak keys that is keyed by strings retains every entry for the lifetime of the table:

[source,tiri]
----
by_name = setmetatable({}, { __mode = 'k' })
by_name['alpha'] = { data = 1 }   -- never released: the key is a string

by_object = setmetatable({}, { __mode = 'k' })
by_object[{ id = 1 }] = 'meta'    -- released once the key table is unreachable
----

The same rule applies to weak values.  A cache declared with `pass:[__]mode = 'v'` that stores strings retains them indefinitely; only collectable values are released.

===== Reference Cycles Through Values

An entry in a table with weak keys is retained when its value holds a reference back to its key.  The value is a strong reference, so the key remains reachable and the pair is never removed:

[source,tiri]
----
cache = setmetatable({}, { __mode = 'k' })
key = {}
cache[key] = { owner = key }   -- value refers to the key
key = nil
processing.collect('full')
-- the entry is still present
----

Store a key-free value, or use `pass:[__]mode = 'kv'`, when a value needs to refer to its own key.

==== Iteration Metamethods

The `pass:[__]pairs` and `pass:[__]ipairs` metamethods customise the behaviour of `pairs` and `ipairs` respectively.  When present on a table's metatable, the runtime calls the metamethod instead of the default iterator.  See <<sec-iteration>> for full details.
